# 代理与出网配置

> 这是 websearch-mcp 的**可选**增强功能。不配也能用 —— 服务直连时能访问
> 国内可达的搜索源（百度 / 必应 / 360 / 微信 / 搜狗等）。配上代理后，
> 才能用上 Google / DuckDuckGo / Brave 这些墙外源，搜索覆盖面显著变宽。

## 为什么需要它

零 API Key 的爬虫式搜索有个绕不过的现实：**Google、DuckDuckGo、Brave
等优质源在墙内不可达**。实测（2026-10-13，中国大陆网络）：

| 源 | 墙内直连 |
|---|---|
| 百度 / 必应 / 360 / 搜狗 / 微信 / 头条 / Mojeek | ✅ 可达 |
| Google / DuckDuckGo / Brave / Wikipedia / GitHub | ❌ 不可达 |
| 公开免费代理池（19710 个样本） | ❌ 能通 Google 的 **0 个** |
| 公共 SearXNG 实例（12 个） | ❌ 全部不可达（域名被 DNS 投毒）|

所以：**想出网，只能用自己的节点。** 本服务不内置、不收集、不代理
任何人的节点 —— 你的订阅链接只在你自己的服务器上。

## 快速开始

### 1. 装 sing-box

服务用 [sing-box](https://github.com/SagerNet/sing-box) 做代理客户端
（支持 ss / vmess / trojan / vless+reality / hysteria2 / tuic）。

```bash
# aarch64（树莓派 / 手机容器 / ARM 服务器）
VER=$(curl -s https://api.github.com/repos/SagerNet/sing-box/releases/latest \
      | grep -o '"tag_name": *"[^"]*"' | head -1 | cut -d'"' -f4)
curl -sL -o /tmp/sb.tar.gz \
  "https://github.com/SagerNet/sing-box/releases/download/$VER/sing-box-${VER#v}-linux-arm64.tar.gz"
mkdir -p /opt/sing-box && tar -xzf /tmp/sb.tar.gz -C /tmp --strip-components=1
cp /tmp/sing-box /opt/sing-box/sing-box && chmod +x /opt/sing-box/sing-box
/opt/sing-box/sing-box version
```

x86_64 把 `linux-arm64` 换成 `linux-amd64`。

### 2. 启动管理面板

```bash
cd /opt/websearch-mcp
export PYTHONPATH=/opt/websearch-mcp/src
export WS_CONFIG_FILE=/opt/websearch-mcp/.env
./venv/bin/python -m websearch.proxy.panel_server
```

首次启动会打印一次**面板口令**，请立即保存：

```
══════════════════════════════════════════════════════════════
 面板口令已生成（只显示这一次，请立即保存到密码管理器）：
   <你的面板口令，形如 32 位随机串>
 口令文件：/opt/websearch-mcp/.env（600 权限）
══════════════════════════════════════════════════════════════
```

### 3. 在面板里填订阅

浏览器打开 `http://<服务器IP>:8500`，输入口令登录，然后：

1. 在「机场订阅」填你的订阅链接
2. 点「保存」
3. 点「启动代理」
4. 点「健康检查」确认能出网

### 4. 让搜索服务走代理

```bash
export WS_PROXY=http://127.0.0.1:17890
```

重启搜索服务后生效。用 `proxy_status` 工具可随时查看状态。

## 安全设计

这一节是给审计者和谨慎的用户看的。**凭据安全是这个功能的底线。**

| 措施 | 说明 |
|---|---|
| 文件权限 600 | `.env` 每次写入后强制 `chmod 600`，目录 700，不依赖 umask |
| 不入 git | `.env`、`singbox.json`、`*.sub` 等在 `.gitignore` 里；启动时还会自检 |
| 面板不回显 | `GET /api/config` 只返回掩码（`https://ab●●●●yz (43 字符) @ host`），永不回传订阅原文 |
| 日志不落凭据 | 订阅拉取失败只报「HTTP 404」不报 URL；解析错误只报「第 3 个节点：vmess 缺 add 字段」 |
| 面板强制鉴权 | 无口令拒绝启动；登录失败 5 次锁 5 分钟；Cookie 不放口令明文 |
| 写入白名单 | 面板不能写任意环境变量；值里禁止换行（防注入额外配置行）|
| 只监听回环 | sing-box 的 HTTP/SOCKS 端口只绑 `127.0.0.1`，不暴露给局域网 |
| 内网直连 | 路由规则里 `ip_is_private` 走 direct，避免自环与无谓流量 |

**关于「面板要不要暴露到局域网」**：默认只监听 `127.0.0.1`（即只能
在服务器本机访问）。如果你要从别的机器访问，两种方式：

- **推荐**：SSH 端口转发 `ssh -L 8500:127.0.0.1:8500 user@server`，
  然后浏览器开 `http://127.0.0.1:8500`。这样面板完全不暴露。
- 不推荐：`WS_PANEL_HOST=0.0.0.0`，此时面板对全网可达，请务必确认
  口令强度并在防火墙限制来源。

## 降级设计：代理挂了不等于服务挂了

用户的代理随时可能失效（节点死、订阅过期、sing-box 被 OOM）。
如果代理失效就让搜索不可用，那是把「增强功能」做成了单点故障。

```
请求 → 代理健康门判定
        ├─ 代理可用  → 走代理（能用墙外源）
        └─ 代理不可用 → 自动降级直连（仍能用国内源）
                        └─ 每 60s 探活，恢复后自动切回
```

**触发降级的条件**（连续 3 次）：

- `ConnectError` / `ProxyError` / 连接超时 / 隧道失败

**不触发降级的条件**（重要）：

- 引擎返回 403、验证码、`marker:verify.css` —— 这说明**代理工作正常**
  （请求确实到达了目标站），是目标站在反爬。把它算成代理故障会导致
  「代理好好的却被降级直连」。

用 `proxy_status` 工具查看当前状态：

```json
{
  "proxy_configured": true,
  "using_proxy": true,
  "bypassed": false,
  "bypass_count": 0,
  "last_error": "",
  "hint": "代理正常，请求走代理出网。"
}
```

## 支持的协议

| 协议 | 支持 | 备注 |
|---|---|---|
| `ss://` | ✅ | SIP002 与旧式 base64 两种编码 |
| `vmess://` | ✅ | 含 ws / grpc / h2 传输 |
| `trojan://` | ✅ | |
| `vless://` | ✅ | **含 Reality**（当前抗封锁主力）|
| `hysteria2://` | ✅ | 含 `hy2://` 简写 |
| `tuic://` | ✅ | v5 |
| `ssr://` | ❌ | sing-box 已移除支持，面板会明确告知 |
| `hysteria://` (v1) | ❌ | 建议换 hysteria2 |
| `snell://` | ❌ | sing-box 不支持 |

不支持的协议会在面板里**逐条列出并说明原因**，不会静默丢弃 ——
你能看到「你 20 个节点里有 3 个是 ssr，没接进来」。

## 故障排查

| 症状 | 原因 | 处置 |
|---|---|---|
| 面板打不开 | 进程没起 / 端口占用 | 看日志；确认 8500 未被占用 |
| 忘记面板口令 | — | 删掉 `.env` 里 `WS_PANEL_TOKEN=` 那行，重启面板会重新生成 |
| 「订阅内容不像节点列表」| 链接失效、机场返回了 HTML | 浏览器打开订阅链接确认；或换 UA 重试 |
| 启动代理报「配置校验失败」| 节点参数不全 | 看面板返回的原因（会指明第几个节点缺什么）|
| 健康检查失败但端口在听 | 节点失效（sing-box 活着）| 换节点；这是为什么探活不用 TCP 判定 |
| `proxy_status` 显示 bypassed | 代理连续失败已降级 | 修好代理后等 60s 自动恢复，或重启服务 |

### proot 容器特别说明

在 Android + proot-distro 这类**无 capability** 环境（`CapEff: 0`）里
跑 sing-box，会遇到：

```
FATAL start service: initialize network: subscribe netlink groups: invalid argument
```

原因是 sing-box 默认要订阅内核网络事件，而 proot 没有 `CAP_NET_ADMIN`。
**本项目生成的配置已经规避了这一点**（不写 `auto_detect_interface`、
不订阅 netlink）。仍会看到一条无害的告警：

```
ERROR network: missing default interface
```

这条只影响「自动选网卡」，不影响 HTTP/SOCKS 代理功能，可以忽略。
